# Claude Code Companion

A dependency-free VS Code extension (`lekra.claude-companion`) that adds the quality-of-life features the official **Claude Code** extension (`anthropic.claude-code`) lacks:

- **Session statuses in the status bar** — `~` working, `?` waiting for you, `V` done, `!` error, with the number of sessions in each state. Click the item to open a menu of this window's sessions; pick one and its Claude tab is focused.
- **Statuses in the tab titles** — `[~] Fix parser`, `[?] …`, `[V] …`, `[!] …` in front of each Claude Code tab title (see [Tab status markers](#tab-status-markers)).
- **Sounds for done / waiting / error** — a rising two-note chime when a turn finishes, a soft double ping when Claude needs your permission or an answer, and a descending tone when a turn fails. The completion chime only plays for turns that lasted at least `doneSoundMinSeconds` (20 s by default), so quick questions stay quiet.
- **Claude subscription limits** — the 5-hour and 7-day windows (plus any extra weekly bucket the API reports) with a graphical bar, pace ("on track" / "slower" / "faster"), a depletion forecast, the reset countdown and threshold alerts. Refreshed every 5 minutes and shortly after a turn finishes.
- **DeepSeek balance and worker spend** — the balance from `api.deepseek.com` and today's / last 7 days' spend of the DeepSeek workers, read from the `ds.py` ledger (`~/.claude/deepseek-ledger.jsonl`). While the DeepSeek routing is on, the balance and today's spend also sit in the status bar.
- **Context-size warning** — a one-time notification when a session's context reaches `contextWarnTokens` (300 000 by default).
- **DeepSeek routing switch** — the menu behind the status bar item and the tooltip show whether new Claude chats go through `api.deepseek.com`, and one click flips it. The switch runs the `claude-ds` script, which owns the key, the backups and the `.gitignore` guard, so the companion never writes that secret itself.
- **Nested sessions are ignored** — DeepSeek workers and `claude -p` runs started from a Bash tool set `CLAUDECODE`; the companion leaves them out of the status bar (opt in with `trackNestedSessions`).

Everything is localized to the VS Code UI language (English, Russian, Simplified Chinese).

## How it works

Statuses come from Claude Code's own HTTP hooks; the only change to the Claude extension is the optional tab-title hook described below.

1. While at least one VS Code window is open, the extension writes HTTP hook entries into `~/.claude/settings.json` (respecting `CLAUDE_CONFIG_DIR`) for `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `Notification`, `Elicitation`, `Stop`, `StopFailure` and `SessionEnd`. Every foreign setting, hook and top-level key is left untouched; a settings file that does not parse is reported and never overwritten.
2. All windows try to listen on `127.0.0.1:47823` (setting `claudeCompanion.port`). The first one wins and becomes the **leader**; the others are followers and retry every 3 seconds. The hook URL always points at the leader.
3. Hook requests carry the owning window id and the `CLAUDECODE` (nested) flag in headers. The leader keeps the shared session store in the extension's global storage and every window renders from it.
4. Session titles and context sizes come from the tail of Claude Code's transcript files, so nothing is read from the Claude extension itself.
5. When the last VS Code window closes, the hooks are removed again — otherwise the CLI would print a "hook failed" line for every event while no companion is listening. Uninstalling the extension removes them too.

Claude limits are fetched from `https://api.anthropic.com/api/oauth/usage` with the OAuth token already stored by Claude Code. DeepSeek data goes directly to `https://api.deepseek.com` (no proxy). See [Privacy](#privacy).

## Tab status markers

VS Code gives no extension access to another extension's tab titles, so the companion inserts two tiny hooks into the Claude Code extension's `extension.js` (the first pristine copy is kept as `extension.js.bak-claude-companion`). The patch is all-or-nothing and self-healing: it is checked on every start and whenever extensions change, so after a Claude Code update it is re-applied automatically and VS Code asks for **one window reload**. If a future Claude build changes that code beyond recognition, the markers switch off with a single warning and everything else keeps working. Without the companion the patched code simply shows the plain title. Turn it off with `claudeCompanion.tabStatusMarkers`.

The same patch names Claude Code tabs after the project (workspace) instead of "Claude Code" and the session titles Claude generates (`claudeCompanion.projectTabTitle`: `always` by default, `untitled` = only until the session gets its own title, `off`). The session titles stay in the status bar tooltip.

## Settings

| Setting | Default | Description |
|---|---|---|
| `claudeCompanion.statusBar` | `true` | Show the Companion status bar item. |
| `claudeCompanion.sessionStatus` | `true` | Show the per-session status counters (`~` working, `?` waiting, `V` done, `!` error). |
| `claudeCompanion.tabStatusMarkers` | `true` | Prefix Claude Code tab titles with the session status (patches the Claude extension, see above). |
| `claudeCompanion.projectTabTitle` | `always` | Name Claude Code tabs after the project: `always`, `untitled` (only until the session has a title) or `off` (same patch). |
| `claudeCompanion.usageInStatusBar` | `true` | Show the 5-hour and 7-day usage percentages in the status bar. |
| `claudeCompanion.soundDone` | `true` | Rising chime when a turn finishes. |
| `claudeCompanion.soundWaiting` | `true` | Double ping when Claude needs you. |
| `claudeCompanion.soundError` | `true` | Descending tone when a turn fails. |
| `claudeCompanion.doneSoundMinSeconds` | `20` | Minimum turn length for the completion chime; shorter turns stay silent (`0` = always play). |
| `claudeCompanion.notifications` | `false` | Native VS Code notification with the session title when a turn finishes. |
| `claudeCompanion.alerts` | `true` | Notify when a Claude limit or the DeepSeek balance crosses a threshold (once per limit window). |
| `claudeCompanion.alertThreshold5h` | `0.8` | Threshold for the 5-hour limit (fraction `0..1`). |
| `claudeCompanion.alertThreshold7d` | `0.9` | Threshold for the 7-day limit (fraction `0..1`). |
| `claudeCompanion.alertDeepseekBelowUsd` | `1` | Warn when the DeepSeek balance drops below this amount (USD); re-arms after it climbs to 1.5× the threshold. |
| `claudeCompanion.contextWarnTokens` | `300000` | Warn once when a session's context reaches this many tokens (`0` = off). |
| `claudeCompanion.manageHooks` | `true` | Add the hooks to `~/.claude/settings.json` while VS Code is open and remove them when the last window closes. |
| `claudeCompanion.port` | `47823` | Loopback port of the receiver on `127.0.0.1`; all windows share one elected listener. |
| `claudeCompanion.proxy` | `""` | Proxy for `api.anthropic.com`. Empty = take `HTTPS_PROXY` / `HTTP_PROXY` from the environment or from `env` in `~/.claude/settings.json`; `"none"` = connect directly; or a proxy URL such as `http://127.0.0.1:8080`. |
| `claudeCompanion.trackNestedSessions` | `false` | Also track nested sessions (DeepSeek workers, `claude -p` from a Bash tool). |
| `claudeCompanion.deepseekToggle` | `true` | Show the DeepSeek on/off switch in the menu and in the tooltip. |
| `claudeCompanion.deepseekInStatusBar` | `true` | While the DeepSeek routing is on, append the balance and today's worker spend to the status bar, e.g. `DS $3.42 (−$0.18)`. |
| `claudeCompanion.deepseekScope` | `"project"` | Which settings file the switch edits: `"project"` (`.claude/settings.local.json` of the first folder) or `"user"` (`~/.claude/settings.json`). |
| `claudeCompanion.deepseekScript` | `""` | Path to the `claude-ds` script; empty = `<claude dir>/deepseek/claude-ds.mjs`. The script is launched through the extension host's own Node, so it needs no PATH entry. |

## Commands

| Command | What it does |
|---|---|
| `Claude Companion: Menu` | The same menu as clicking the status bar item (sessions, then actions). |
| `Claude Companion: Usage` | A full usage report: every limit with a bar, pace and forecast, the DeepSeek balance and the worker spend. |
| `Claude Companion: Refresh Limits` | Refetches the Claude usage and DeepSeek data now. |
| `Claude Companion: Test Sounds` | Plays the done / waiting / error sounds one after another. |
| `Claude Companion: Install Hooks` | Writes the HTTP hooks into `~/.claude/settings.json` for the current port. |
| `Claude Companion: Remove Hooks` | Removes only the companion's hook entries, keeping everything else. |
| `Claude Companion: Toggle DeepSeek` | Switches the DeepSeek routing for new chats on or off (runs `claude-ds`); also the first item of the menu. |
| `Claude Companion: Diagnostics` | A state report: versions, hook status, port and leader role, live windows, session store and the usage cache. |

## Install from a .vsix

Requirements: VS Code 1.100 or newer, the official **Claude Code** extension, and a logged-in Claude Code CLI (subscription limits additionally need a Claude subscription login).

```bash
code --install-extension claude-companion-0.1.0.vsix
```

Reload the window. Hooks are installed on activation. For the tab markers the Claude extension is patched on the first start and VS Code asks for one more reload. To uninstall, remove the extension — its `vscode:uninstall` script removes the hook entries.

Building from source:

```bash
python scripts/gen-assets.py                 # font, icon and sounds (deterministic)
python scripts/build-vsix.py . 0.1.0 claude-companion-0.1.0.vsix
node --test "test/**/*.test.js"
```

`scripts/release.ps1` (Windows) bumps the version, validates, builds, installs locally, tags and publishes a GitHub release.

## Privacy

- The Claude OAuth token is read locally from `~/.claude/.credentials.json` (or `CLAUDE_CONFIG_DIR`), sent only to `api.anthropic.com` in the `Authorization` header, and never logged. The companion **never refreshes** the token — refreshing would rotate Claude Code's own login.
- The DeepSeek API key is read from `DEEPSEEK_API_KEY`, `~/.claude/secrets/deepseek.json` or `~/.kimi-code/config.toml` and sent only to `api.deepseek.com`. Keys are never logged.
- The hook receiver listens on `127.0.0.1` only. There is no telemetry, no account and no other network traffic; balances, spend and limits are cached in the extension's global storage for the next window.

## Troubleshooting

- **Nothing appears in the status bar.** Run `Claude Companion: Diagnostics`. It shows whether the hooks are present, who the leader is, which windows are registered and what the store contains.
- **The port is taken.** Another process may hold `127.0.0.1:47823`; change `claudeCompanion.port` and reload. Every window picks up the new port, and the hooks are rewritten.
- **Limit requests fail behind a proxy.** Set `claudeCompanion.proxy` to the proxy URL, or leave it empty to use `HTTPS_PROXY` / `HTTP_PROXY` from the environment or from `env` in `~/.claude/settings.json`. Use `"none"` to force a direct connection. The DeepSeek balance always connects directly.
- **The CLI prints "hook failed".** Hooks are installed only while a companion window is running; after a crash they are removed on the next VS Code start. Use `Claude Companion: Remove Hooks` if VS Code will stay closed for a while.
- **Sounds are silent.** Check the sound settings and run `Claude Companion: Test Sounds`. On Windows the bundled WAVs are played through PowerShell `SoundPlayer`, on macOS `afplay`, on Linux `paplay` must be installed.
- **A session is missing from the menu.** Sessions of other VS Code windows are listed for information only (opening them here would start a second CLI on the same session). Nested sessions are hidden unless `trackNestedSessions` is on. A session disappears 12 hours after its last event.

The extension writes an activity log to **View → Output → "Claude Code Companion"**.
